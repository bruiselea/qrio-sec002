# 所有者登録・vaultの検証範囲

新しい公開版の登録は、ドアに設置済みの稼働個体へ再実行していません。以前その個体で使用した登録メッセージ・認証処理をもとに、公開用の保存・再開・出力の処理を追加しています。**新規個体への公開コマンド一式、XIAO経由の新規登録は実機通し試験未実施**です。

## 再現できる合成試験

リポジトリのルートで、`requirements-onboarding.txt`を入れたPythonから実行します。

```sh
python -m unittest discover -s onboarding/tests -v
python relay/verify.py
python -m unittest discover -s tests -v
```

新しい試験にAPK・実機・ネットワーク接続・本人の鍵は使いません。係数表は人工的なデータ、RSA鍵は試験時に生成したものです。

2026-11-03、Windowsの専用venv（Python 3.14）とPiの独立した一時ソース配置（Python 3.11）で、登録関連29件・中継13件・本体差分ツール11件を確認しています。Windowsは掲載した`requirements-onboarding.txt`から新しく環境を作りました。試験は稼働中のゲートウェイ設定・実機の所有者登録を変更しません。

- MQのビット位置とワード順、サイズ不正、APK内ライブラリーの欠落・重複・未知の指紋・サイズ超過を検査。
- 旧v1互換の独立した暗号化処理、Unicodeを含むパスフレーズ、改ざん・誤入力・サイズ上限を検査。
- 上書き拒否、更新前暗号文の保全、置換失敗時の元ファイル保全、OSロック、POSIXのモード600を検査。
- 模擬本体がAES暗号文、双方向HMAC、RSA公開鍵と署名、20バイトGATTフレームを確認。
- 各段階の応答喪失、カード照合失敗、ディスク保存失敗で止まり、別の鍵を作り直さないことを検査。
- 登録ACKだけでは出力しないこと、読み取り専用検証、旧vaultの移行、失敗時の検証印失効、必要項目だけの出力を検査。
- 広告の0件・重複、XIAO識別と切断処理、BLE接続キャンセル時の後処理、CLIの物理準備指定、非表示入力が使えない端末での拒否、例外の秘密情報を出力しないことを検査。

登録時には公開ランタイムの接続と通常GATTフレーミングだけを再使用します。所有者カードの手順からファーム書き込み・生メモリー操作・モーター命令へ進む実装はありません。

## 手元の保管APKとの比較

2026-11-03、本人が保管している旧APKの対応ライブラリーを読み、係数抽出が元の実装と一致し、9つの合成入力でMQ公開鍵生成が元の実装およびネイティブ処理のメモリー内エミュレーションと一致することを確認しました。APK・ライブラリー・係数表・その抽出結果は配布しません。この比較は実機での新規登録成功を意味しません。
