# 有線キットの検証範囲

日本語 | [English](TESTING.en.md)

## 過去に実機で確認した基礎処理

2026-11-03、所有するQ-SL1の1個体とC3 SuperMiniで、GPIO5→F9、GPIO4→F10、GND→F11の接続を使用しました。C3の65,536バイトの単体ループバック、115200 8N1のROM応答、EEPROM64KiBの独立2回取得、既存ROMのWP設定による書き込みと読み戻し、一時設定の復元を確認しました。

復旧時はDEV001をDS2へ配置・選択し、配線を外した電池起動と既存所有者認証まで確認しています。最初のWP未設定のマーカー要求はACKだけでEEPROMを変更していませんでした。単独の1バイト復元による純正起動の実機確認、公開用CLIの実機通し試験、通常のUSB UART変換器、別個体での動作は未確認です。

## 公開用の合成試験

リポジトリのルートで、`requirements-wired.txt`を入れたPythonを使います。シリアルポート・BLE・SSH・実機・純正ファームを使いません。

```sh
python -m unittest discover -s wired/tests -v
python -m unittest discover -s tests -v
```

2026-11-03、掲載する依存だけを入れた新しい専用venvで確認しました。Windows（Python 3.14）は有線27件が成功、Pi（Python 3.11）の独立した一時配置では26件が成功し、Windows専用DPAPI試験1件をskipしました。既存の本体ツール11件も両環境で成功しています。

合成試験は以下を確認します。

- 分割HCI応答、拒否、短い送信、期限切れ、コマンドエコー、不正フレームでの停止と再送禁止。
- EEPROM・固定ROM・WP欄だけの読み取り、固定WP値と先頭1バイトだけの書き込み制限。
- 既存の無線バックアップと共通の暗号化、誤パスフレーズ、上書き拒否、POSIXのモード600。
- Windows DPAPIからの変換。Windowsでは合成データを暗号化して試験し、LinuxではWindows専用試験をskip。
- 同一SS1、固定純正DS1、正常なマーカーだけを受け付け、別個体相当のSS1・破損DS1・未知のマーカーを拒否。
- DS2の16バイト境界ごとの中断状態1,678通りでも、予定変更が先頭1バイトだけであること。
- 直前の独立2回読み出し・暗号化保存と、指定スナップショットの一致。保存失敗・不一致ならRAM・EEPROMの書き込み前に停止。
- ROM／WP設定の不一致、ACKだけで物理変化なし、応答喪失、対象外変更、ジャーナル保存失敗、WP復元失敗を成功にしないこと。
- 復旧CLIは既定でオフライン計画とし、実行の物理準備引数がなければポートを開かないこと。

純正DSを配布しないため、試験内では人工的なDSとその指紋を使います。本番の固定ハッシュを無効にするCLI引数はありません。モックでの成功は、実機のEEPROM書き込み・起動を確認したことにはなりません。

## C3ビルドと保管データとの照合

公開するC3スケッチは、実機ループバックに使用した独自ソースと同一です。2026-11-03、公開する配置からArduino ESP32 Core 3.3.7でビルドに成功しました。プログラム303,628バイト、静的RAM14,968バイトで、機器への書き込みは行っていません。生成したファームはこのリポジトリへ同梱しません。

同日、本人が保管する正常時と故障時の暗号化データをメモリー上で読み、公開版の復旧ポリシーが先頭1バイトだけを変更する計画になることも確認しました。故障時の独立2回の一致、配備SEC001とDS2の一致、SS2の予定値、ROM指紋、後続のDEV001起動・認証の記録も再照合しています。ファーム・所有者領域・全EEPROMハッシュは公開しません。この照合は、公開コマンドを実機へ実行したことを意味しません。
