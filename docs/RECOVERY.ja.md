# 中断時の判断と有線復旧の準備

旧v0.1.0 ZIPは初回の無線導入ツールで、有線復旧プログラムを含みません。**最新ソースには[有線バックアップ・限定復旧キット](../wired/README.ja.md)を追加しています。** パスフレーズ付きの暗号化保存と既存DPAPIバックアップのローカル変換に対応し、正常時の同一個体バックアップ・無傷の純正DS1・SS1がある場合だけ起動マーカーを復元します。公開版の復旧コマンドは実機通し試験未実施です。C3用はソースを収録し、生成済みバイナリは含めません。以下は確認済みの復旧方針と配線情報です。

[SEC001の文鎮化原因と実施記録](BOOT_FAILURE.ja.md)では、確認済みの事実と原因候補を区別しています。最初のマーカー書き込みはACKだけで変化せず、後続のWP設定とDEV001配置・選択により起動復帰を確認しました。

## 段階ごとの停止位置

| 止まった段階 | 本体への変更 | 次に確認すること |
| --- | --- | --- |
| scan / backup / build | EEPROM書き込みなし | 起動音・広告、対象アドレス、他の接続ソフト、受信距離。別の版やハッシュへ強制適用しない |
| stageの途中 | DS2の一部、一時的なRAMのWP設定 | SS1は純正のまま。終了後15秒以上待ち、純正の起動を確認する。レポートと新しい読み出しで状態を確認してから再計画する |
| activateのSS2作成途中 | SS2の一部。最終コミット前ならSS1は純正 | エラー時は同じ接続が生きている間に限り、SS1選択の確認・復元を試す。成功はレポートの`pre_boot_selector_recovery_verified`で判断する |
| activateのSS1コミット以降 | SS2がSEC002を指し、SS1先頭が無効 | 広告と版表示を確認する。起動しなければ有線ROMへ進む。コマンド再実行を無線復旧策にしない |
| SEC002の正常起動後 | 無線FWUと旧OTAを閉鎖済み | 無線でのメモリ読み出し・更新が通らないのは予定された動作。以後のファーム保守は有線 |

`.private/*.receipt.json`に完了した工程を記録します。`completed`や`boot_verified`がない結果を成功とは扱いません。接続が切れた後の自動書き込み再送はありません。エラーの後に作られた中間バックアップを、最初の`original.qsb`へ上書きしないでください。

stageでは純正DS1を選んだまま予備領域だけを書きますが、電源断時のEEPROM内部動作や、全ハードウェア故障まで保証する仕組みではありません。SEC002の起動時チェック失敗では広告を出さないため、その場合もUARTが必要です。

## 確認できた有線経路

アプリが起動しない個体でも、ROMのUARTプログラミングモードには接続できました。用意するものは3.3VロジックのUART変換器、12ピン・0.5mmピッチFPCへの接続手段、3本の配線、正常なCR123A電池、手元の暗号化バックアップです。ESP32-C3 SuperMiniも、適切なUSB CDC–UARTブリッジを書き込めば変換器として使えます。

このプロジェクトで使ったC3ブリッジの配線は次のとおりです。F番号は**Q-SL1側フラットケーブルのピン番号**です。FPCの表裏で左右を取り違えないよう、接続基板の番号を確認します。C3のGPIO番号とは別の番号です。

| Q-SL1 | C3 SuperMini | 方向 |
| --- | --- | --- |
| F9（本体の書込UART RX） | GPIO5（ブリッジTX） | C3 → Q-SL1 |
| F10（本体の書込UART TX） | GPIO4（ブリッジRX） | Q-SL1 → C3 |
| F11 | GND | 共通GND |

UARTは115200bps、8N1、ハードウェアフロー制御なしです。これは上記の専用ブリッジ設定です。未設定のC3へ配線するだけではUART変換器にはなりません。

本体の電池とC3のUSBを抜いて配線し、C3のUSBを先に接続してTXをアイドルHighにしてから本体へ電池を戻すと、対象個体ではROMモードに入りました。**F1・F2・F3、C3の5V・3V3は接続しません。本体は電池で給電します。** 通常起動を確認するときは電池を抜き、C3と3本の信号線も外してから、電池だけで起動します。

## ROM側で復旧プログラムが満たす条件

1. 消去やminidriverの転送に先立たず、HCI `Read Local Version`（0x1001）と`Read RAM`（0xFC4D）でROMとEEPROMを確認する。全64KiBを独立に2回取得し、一致した暗号化バックアップを別名で保存する。
2. 保存済みの**同じ個体**のSS1本体と一致し、純正DS1のハッシュも一致することを確認する。別個体の全EEPROMや所有者領域を移植しない。
3. 必要なROMドライバ／WP設定は元の値を保存・照合し、確認済みの最小変更に限定する。今回の対象ROMではRAM `0x2008AB`のWP設定と`0x200DA8`の既存ROMコールバック参照を使った。別のROMへこれらを無条件に書かない。
4. 純正DS1とSS1の残り39バイトが無傷なら、永続変更はEEPROMアドレス0のSS1先頭1バイトを`0x01`へ戻すだけに限定できる。`Write RAM`（0xFC4C）のEEPROM別名`0xFF000000`を使い、書込ACKが不明な場合は自動再送しない。
5. 直後に全64KiBを再読取し、予定した1バイト以外が変わっていないことを照合する。一時的なRAM設定も復元し、配線を外して電池起動を確認する。

これは今回の配置に基づく方式です。DS1・SS1本体が壊れている場合に同じ1バイト復元を行っても復旧しません。コマンドは[最新ソースの有線キット](../wired/README.ja.md)にあり、旧v0.1.0 ZIPだけでは実行できません。有線手段を用意できない状態で「失敗しても必ず元へ戻せる」と考えてactivateしないでください。

FPC端子や筐体についての先行調査: [bakueikozo/qriohack](https://github.com/bakueikozo/qriohack)。このZIPには同リポジトリの写真・プログラムを転載していません。
