# 検証範囲と再現方法

## 同梱の合成テスト

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m qsl1sec --help
```

Bluetooth・所有者鍵・純正ファームを使わずに実行できます。11件のテストで、差分の範囲・レコード形状・重複拒否、書込ポリシー、暗号化保存・改ざん拒否、ACLパケットと古い接続ハンドルの対象判定、受信キャンセルの後処理、ROM/runtime不一致時の書込拒否、予備領域の保全、全コミット書込点での中断・ACK消失を検査します。物理EEPROMの電源断挙動や、無線干渉・実モーターを再現するテストではありません。

## 私有の参照データで確認したこと

配布する固定差分を手元の純正DSへ適用し、実機で稼働しているSEC002と完全一致することを確認しました。

| 値 | SHA-256 |
| --- | --- |
| 純正DS1・26,845バイト | `4679b688063dac92d7c326f3e98ba429291bf1140afc2f4b96a1694cb8741c81` |
| SEC002 DS・26,845バイト | `ccf6a88bfb1d9b4dd7568bc8abbb386522518435efa564041ecfd29baeec2e82` |

全EEPROMの個体固有ハッシュは対応条件にしていません。SS1は各個体から複製し、起動先だけを変更します。DSレコードの種類・長さ・順序、RAM配置、CRT/BSS/heap境界を元と一致させ、追加DSレコードや新しいRAM領域は作っていません。

参照ファーム・EEPROM・所有者情報は私有であり、合成テストに含めません。公開ZIPだけで実機試験全体が再現できるという主張はしません。

## 実機で確認したこと

2026-11-03までに所有する1個体で確認しました。

- 純正→DEV001→純正: Linux raw HCI / 独自L2CAPによる予備領域転送とSS選択切替。
- SEC002: ROM UARTによる予備領域転送、全EEPROM読み戻し、起動先切替。
- SEC002の2回の電池再起動、版表示、既知のFWU読取要求の無応答とその後のGATT生存。
- 正規所有者認証、ReadStatus、認証された旧OTA op9の拒否、施解錠の正常完了応答。直接試験時のモーター回転は目視未確認。
- 既存HomeKit接続の再開と、都度Bluetooth接続を維持するレイテンシ改善。ホーム操作からの厳密な時間測定は別途必要。

**この配布版の純正→SEC002全無線導入は、実機で最初から最後まで試していません。** 稼働中の対策を外して再試験することはせず、固定イメージ一致・合成障害試験・Linux上のオフライン試験で配布版を確認します。別個体・別版・全電源断条件・BLE全実装の安全性は未確認です。
